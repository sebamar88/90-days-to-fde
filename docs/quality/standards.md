# Quality standards

## Lesson acceptance

Every published lesson must include valid front matter (`day`, `phase`, `status`, `title`, `estimated_effort`) and these sections: why it matters, scenario, outcomes, exercise, deliverable, assessment, and reflection. A phase review may use a rubric instead of a separate assessment section only when its scoring and pass threshold are explicit.

## Curriculum quality

- Outcomes use observable verbs and fit the target learner.
- Activities produce a named artifact or demonstrated behavior.
- Assessments state evidence, criteria, and a meaningful pass/revise condition.
- Scenarios label simulation, keep data synthetic, and avoid invented validation claims.
- Lessons build on prior work and name prerequisites when needed.
- Technical recommendations explain constraints and trade-offs; AI is not presumed necessary.
- Vendor-specific details identify provider and date checked; core outcomes remain provider-agnostic.
- Advice involving security, privacy, safety, or cost includes a practical check or escalation boundary.

## Editorial and accessibility

- Use concise, direct English and define specialized terms on first use.
- Use descriptive link text, meaningful heading order, and text alternatives for visual material.
- Use tables only when comparison benefits from tabular layout; ensure they read in narrow screens.
- Avoid color-only meaning, unexplained acronyms, and claims that imply job guarantees.
- Keep required work distinct from optional extensions.

## Review checklist

Reviewers should check factual support and source freshness, learner effort, sequence, inclusion/accessibility, privacy/security, license/attribution, and whether the rubric can be applied consistently. CI catches structure; human review owns pedagogy and judgment.
